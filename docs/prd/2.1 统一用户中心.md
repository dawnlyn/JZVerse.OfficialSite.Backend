# 2.1 统一用户中心
## 2.1.1 功能描述
统一用户中心模块是九州寰宇平台的核心枢纽，它集成了用户身份认证、权限管理、服务聚合与个性化导航四大核心能力。用户通过一次登录即可访问平台内所有已接入的服务，无需重复注册或切换账号。该模块不仅提供基础的身份验证功能，还通过智能推荐和场景化入口，将分散的服务整合为连贯的用户体验，真正实现“一站式聚合”的核心价值。
## 2.1.2 用户场景

| 场景类型      | 使用角色    | 具体场景描述                                              |
| --------- | ------- | --------------------------------------------------- |
| 首次访问与注册   | 新用户     | 通过多种方式（手机号、邮箱、第三方账号）注册账号，完成基础信息填写和兴趣标签选择，进入个性化引导流程。 |
| 日常登录与身份验证 | 所有用户    | 使用统一身份快速登录平台，系统自动识别用户身份并加载个性化设置，无需重复认证。             |
| 个人信息管理    | 所有用户    | 在个人中心查看和编辑个人信息，进行安全设置如密码修改、手机邮箱绑定、实名认证等操作。          |
| 平台导航与搜索   | 所有用户    | 通过全局搜索功能（支持免登录使用）快速查找平台内容和服务，或通过清晰导航菜单定位所需功能。       |
| 个性化服务发现   | 所有用户    | 在首页根据AI智能推荐获取个性化服务卡片，基于兴趣标签和使用习惯发现新内容。              |
| 跨场景内容创作   | 内容创作者   | 以统一身份在博客、项目公示等场景发布内容，使用丰富编辑工具，管理内容版本，并分享到其他平台。      |
| 社区深度互动    | 社区用户    | 基于统一身份加入兴趣社群，参与评论点赞、私信群聊等互动，建立线上社交关系。               |
| 多设备多任务同步  | 移动/多端用户 | 在不同设备间保持登录状态、任务进度和数据同步，实现无缝切换体验。                    |
| 隐私与安全管理   | 隐私敏感用户  | 设置个人信息可见范围，管理数据权限，查看安全日志，确保数据安全可控。                  |
## 2.1.3 核心价值
- 统一身份，一次通行：构建统一身份认证体系，实现全平台服务无缝访问，消除重复登录障碍。
- 智能推荐，精准直达：基于AI算法的个性化推荐，让用户快速发现所需内容和服务，提升使用效率。
- 数据贯通，体验连贯：跨业务场景数据互通，用户状态实时同步，创造无缝连贯的数字体验。
- 创作自由，分享便捷：提供完整的内容创作、管理和分享工具链，支持用户建立个人品牌。
- 社区归属，深度互动：基于统一身份的兴趣社群体系，重建有温度的线上社交关系。
- 安全可靠，隐私可控：端到端的数据加密与备份，灵活的隐私权限设置，保障用户数据安全。
- 生态扩展，标准对接：为平台生态扩展提供标准化的身份与入口接口，降低集成成本。

## 2.1.5 需求详述
### 2.1.5.1 身份管理
#### 2.1.5.1.1 用户注册与登录
- 注册：
	- 新用户注册时需同意用户协议和隐私政策
	- 手机号注册：验证码验证，设置密码
	- 邮箱注册：发送验证邮件，设置密码
	- 账密注册：设置用户名，设置密码
	- 除了手机号和邮箱注册外，均需绑定邮箱才能注册成功
	- 非账密注册需要填写用户名，用户名会检测重复，不区分大小写
	- 所有情况均需要填写昵称和头像，昵称不检测重复，头像默认使用系统默认头像，可不改
	- 发送验证码间隔60s
	- 密码要求：6-32位，最低要求小写英文+数字
	- 第三方快捷注册：支持微信、QQ、微博、GitHub等主流平台
	- 第三方注册后需绑定现有账号或创建账号
	- 新注册会需要填写基本信息，可跳过，生日和实名必填
	- 多层次风控：
		1. 前端：图形验证码、行为验证（如拖拽滑块）。
		2. 后端：IP/设备指纹频率限制、号码邮箱信誉库、与第三方风控服务（如数美、顶象）集成
- 登录：
	- 账号密码登录：支持手机号/邮箱/用户名+密码
	- 验证码登录：手机/邮箱验证码登录
	- 扫码登录：移动设备扫码登录
	- 一键登录：手机号一键登录（如未注册直接注册，用户名随机，密码无）（移动端）
	- 第三方授权登录：跳转至第三方平台授权
	- 生物识别登录：支持指纹、面容识别（移动端）
	- 单点登录（SSO）：用户在一个子系统登录后，可免登录访问所有已接入的子系统
	- 移动端登录需要勾选同意协议，服务端提示：登录后自动同意协议
	- 无密码认证：
		- 遵循FIDO/WebAuthn标准
		- 用户公钥存储于平台，私钥留存于用户设备（安全芯片/认证器），平台不掌管私钥
	- 登录状态保持：默认保持7天登录状态，可设置“记住我”
#### 2.1.5.1.2 个人信息管理
- 基础信息：昵称、头像、性别、生日、地区、个人简介等可编辑字段
- 头像管理：支持上传、裁剪、选择系统头像、历史头像
- 联系信息：手机号、邮箱（支持绑定多个邮箱和手机）
- 实名认证：支持身份证、护照等证件实名认证（可选）
- 兴趣标签：用户可选择多个兴趣标签（技术、教育、娱乐、生活等），用于个性化推荐
- 隐私设置：控制哪些信息对他人可见
- 高级信息：地址信息、教育经历、工作经历、职业信息、银行卡绑定、第三方账号关联、简历、我的收藏、作品集、浏览记录、发票抬头、我的评论
- 平台主题：设置平台的主题样式，也可设置单个模块的
- 平台插件：开关平台的部分插件功能，例如：Live2D看板娘、背景音乐等
- 偏好设置：平台各模块偏好设置
- 身份管理：企业、个人
- 数据可移植性：在用户个人中心提供“导出我的数据”功能。后台任务将用户所有数据（资料、内容、互动记录）打包成标准格式（如JSON, CSV），供用户下载
- 动态更新用户协议：用户再次登录时，强制弹出新协议要求同意。对于长期不登录的用户，在首次登录时触发。不同意新协议的用户，只能使用浏览等基础功能，无法进行写操作
- 未成年人年龄验证机制：结合行为数据判断。对于疑似未成年账号，限制其数据被用于个性化广告推荐，并启用防沉迷模式（如使用时长限制）
- 数据最小化：在注册和收集信息时，不仅合法，更要合理。思考每个要求的信息字段是否绝对必要，能否后续再收集
### 2.1.5.2. 统一入口
#### 2.1.5.2.1 平台首页/个人中心
- 首页可自定义，使用可视化编辑器，通过调整小组件进行自定义
- 提供快捷入口，以小组件的形式
- 提供数据报表，以小组件的形式：收入、粉丝等数据（如有）
#### 2.1.5.2.2 智能服务推荐
- 推荐算法：
	- 协同过滤：User-Based CF 和 Item-Based CF 混合，基于用户行为相似度的服务推荐
	- 特征工程：用户特征（ demographics、行为序列）、内容特征（标签、热度）、上下文特征（时间、地点、设备）
	- 深度学习：使用Transformer模型处理用户行为序列
	- 强化学习：基于用户反馈动态调整推荐策略
	- 内容推荐：基于兴趣标签和服务特征匹配
	- 上下文推荐：结合时间、地点、设备等上下文信息
	- 混合推荐：多种算法加权融合，动态调整权重
	- 实时计算：使用Flink进行实时特征计算和模型预测
- 推荐展示：
	- 服务卡片：图文结合的服务入口卡片，显示服务名称、简介、热度、个性化匹配度
	- 推荐理由：显示“根据您的兴趣推荐”、“热门服务”、“好友也在用”等推荐理由
	- 反馈机制：支持“不感兴趣”反馈，优化后续推荐
	- 差分隐私：在收集用户行为数据用于AI训练时，可采用差分隐私技术，在保护个体隐私的同时，仍能获取准确的群体趋势。
	- 解释权：当AI推荐内容时，应提供用户质疑的权利。例如，用户问“为什么给我推荐这个？”，系统应能给出基于标签或行为的、普通人能理解的解释，而不是“黑箱”算法。
- 推荐维度：
	- 用户画像：年龄、职业、兴趣标签
	- 行为历史：浏览、收藏、使用频率
	- 社交关系：关注用户的使用偏好
	- 实时场景：时间、地点、天气、设备类型
	- 热门趋势：平台内热门服务
- 兴趣标签管理：
	- 系统标签：平台预定义的兴趣分类标签（技术、生活、娱乐、学习等）
	- 标签选择：注册时和设置中可选择兴趣标签
	- 标签调整：根据用户行为自动调整标签权重，也可手动调整
#### 2.1.5.2.3 全局搜索与导航
- 搜索功能：
	- 支持免登录搜索：未登录用户可搜索公开内容和服务
	- 多类型搜索：支持内容、服务、用户、社群等多维度搜索
	- 智能提示：输入时实时显示搜索建议和热门搜索词
	- 高级筛选：支持按类型、时间、热度、相关性等条件筛选结果
	- 关键词搜索：支持中文分词、拼音搜索
	- 语义搜索：理解用户意图，提供智能建议
	- 搜索结果：分类型展示，支持按相关性、时间、热度排序
	- 搜索历史：记录用户搜索历史，提供快捷重搜，未登录记录在本地
	- 搜索范围：覆盖博客文章、项目公示、工具、课程、用户、社区帖子等全平台内容
- 导航系统：
	- 主导航菜单：固定位置的一级导航，按功能模块分类
	- 面包屑导航：清晰显示当前位置和路径
	- 快捷导航：支持键盘快捷键（如Ctrl+K打开搜索）
#### 2.1.5.2.4 服务目录与快捷方式
- 服务分类：按功能领域分类（创作工具、学习资源、生活服务、娱乐休闲等）
- 服务目录：
	- 树状结构展示：按功能分类展示所有可用服务
	- 服务状态显示：显示服务是否可用、维护中、需付费等状态
	- 服务详情：点击可查看服务简介、使用指南、相关资源
- 快捷方式管理：
	- 自定义添加快捷方式：从服务目录拖拽或点击添加
	- 快捷方式排序：支持拖拽调整顺序，可置顶常用服务，可收藏常用服务
	- 自定义首页：用户可自定义首页展示的服务卡片，支持拖拽排序、分组管理
#### 2.1.5.2.5 消息通知中心
- 消息聚合：
	- 系统通知：平台公告、系统维护、安全提醒
	- 社交通知：评论回复、点赞、关注、私信、@提及
	- 业务通知：订单状态、课程更新、项目动态、审核结果
	- 聚合展示：所有子系统的通知统一在消息中心展示，按不同的类别进行分类收纳
- 消息管理：
	- 统一收件箱：所有消息按时间线聚合展示
	- 分类筛选：按消息类型、发送者、时间、重要性、未读/已读筛选
	- 批量操作：支持一键已读、删除、归档、跳转到相关页面
	- 推送设置：支持按消息类型设置推送方式（应用内、短信、邮件），哪些通知接收推送、推送频率等

## 2.1.7 详细用例
### 用例1：数字原生代学生首次注册与学习路径探索
- 用例描述：一名大学生首次使用九州寰宇，注册账号并探索学习资源 
- 主要参与者：学生用户、统一身份系统、AI推荐系统、在线教育模块 
- 前置条件：平台已接入多个教育服务商，AI推荐模型已训练 
- 基本事件流：
	1. 学生通过手机号注册账号，选择“技术学习”、“编程开发”、“人工智能”等兴趣标签
	2. 系统根据标签推荐Python入门课程、技术博客专栏、开发者社区等学习资源
	3. 学生点击Python课程，系统记录学习兴趣，在首页增加“编程学习”服务卡片
	4. 学生完成第一节课后，系统推荐相关实践项目和学习伙伴
	5. 学生在项目公示模块发布第一个小项目，获得社区反馈和点赞
- 扩展事件流： 
	2a. 推荐内容不相关：学生点击“不感兴趣”，系统调整推荐策略 
	4a. 学习遇到困难：系统检测到学习进度停滞，推荐辅助资料或问答社区
### 用例2：都市白领日常通勤中的效率工具使用
- 用例描述：白领用户在通勤途中使用平台工具处理工作事务
- 主要参与者：白领用户、统一入口、工具集合模块、消息通知中心
- 前置条件：用户已登录，工具集合模块已集成文档处理、思维导图、日历等工具
- 基本事件流：
	1. 用户在地铁上打开九州寰宇，系统根据时间（上班途中）和位置推荐“今日待办”、“快速笔记”、“通勤阅读”服务卡片
	2. 用户点击“快速笔记”记录会议要点，内容自动保存到个人云笔记
	3. 用户切换到“文档处理”工具，编辑昨晚未完成的报告
	4. 编辑中途下车，系统自动保存编辑状态，同步到用户手机和办公室电脑
	5. 用户到达办公室后，在电脑上继续编辑，系统恢复之前的编辑状态
- 扩展事件流： 
	3a. 需要复杂格式：系统检测到文档格式需求，推荐更专业的文档处理工具
	4a. 网络中断：系统本地保存编辑内容，网络恢复后自动同步
### 用例3：内容创作者跨平台内容发布与管理
- 用例描述：独立开发者创作技术文章并多渠道发布
- 主要参与者：创作者用户、内容编辑系统、版本控制系统、分享模块
- 前置条件：用户已有一定粉丝基础，平台支持多平台分享接口
- 基本事件流：
	1. 创作者在博客系统使用Markdown编辑器撰写技术文章
	2. 撰写过程中多次保存草稿，系统记录每个版本
	3. 文章完成后，设置标签“技术分享”、“开源项目”、“教程”
	4. 一键发布到平台博客，同时生成分享卡片
	5. 通过分享模块将文章同步到个人技术博客、知乎专栏、微信公众号
	6. 各平台反馈数据聚合到内容分析面板
- 扩展事件流： 
	5a. 平台接口限制：某个平台分享失败，系统提示失败原因并提供手动分享链接
	6a. 发现侵权转载：通过内容监测发现未授权转载，系统提供侵权举报流程

## 2.1.10 关键技术实现
- 统一身份认证：
	- 对第三方服务采用OAuth 2.0 + OpenID Connect协议栈，对内采用JWT
	- 内部JWT设计：`登录时获取 -> 本地存储 -> 访问接口携带 -> 后端验证 -> 检查白名单 -> 检查黑名单`
	- JWT令牌设计：包含用户ID、角色、权限、有效期等信息
	- JWT Payload 和Jwt签名均需加密
	- 令牌刷新机制：短令牌（7天）配合长刷新令牌（30天）
	- 多设备管理：支持同时登录设备数限制，设备指纹识别
- 智能推荐系统：
	- 特征工程：用户特征（ demographics、行为序列）、内容特征（标签、热度）、上下文特征（时间、地点、设备）
	- 算法模型：
		- 协同过滤：User-Based CF和Item-Based CF混合
		- 深度学习：使用Transformer模型处理用户行为序列
		- 强化学习：基于用户反馈动态调整推荐策略
	- 实时计算：使用Flink进行实时特征计算和模型预测
	- AB测试框架：支持多算法并行测试，实时评估效果
